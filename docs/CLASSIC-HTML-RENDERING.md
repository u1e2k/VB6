# Classic HTML rendering: attribution and validation

## Staircase bevels

Jordan Scales (`jordanscales`) pointed out the 45-degree corners produced by
multicolored CSS borders in [Hacker News comment 49963404](https://news.ycombinator.com/item?id=49963404).
His recommendation was the layered inset `box-shadow` technique used in
[98.css](https://jdan.github.io/98.css/). See his
[explanation](https://notes.jordanscales.com/98-css-reflections#when-buttons-were-good).

`src/theme/bevels.css` adapts this technique using VB6's semantic theme colors.
The original copyright and MIT permission notice from
[98.css/LICENSE](https://github.com/jdan/98.css/blob/main/LICENSE) are retained in
`LICENSES/98.css.txt` **and the distributed CSS itself**, including exported
standalone applications. No third-party font files or JavaScript were imported.
The attribution is in the source as well as this document.

The overrides are intentionally limited to rectangular classic controls. Their
removed borders are compensated by padding to preserve authored outer bounds
and content origins. Native radio circles, user-authored shapes, editor text,
flat menu items and selection/focus behavior are not globally replaced.
Forced-colors mode keeps real borders rather than relying on suppressed shadows.
Theme tokens are redeclared at every theme boundary for embedded runtime forms.

## Stable HTML list rows

`src/ide/virtual-list.js` retains visible ToolList rows and updates only changed
labels, icons, selection and accessibility attributes. No-change paint performs
no DOM writes. Scrolling creates only newly visible overscan rows. The map is
bounded by visible rows and is cleared when disposed. Existing selection,
keyboard navigation, incremental search, detached-window adoption and resize
scheduling are preserved.

This is original JavaScript. Its read-before-write layout batching is informed
by Jeremy Wagner, Paul Lewis and Barry Pollard, [Avoid large, complex layouts
and layout thrashing](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing).
It is separate from the specific HN bevel recommendation. Source attribution is
included beside the changed code. Benchmarks compare the actual previous paint
method against retained rows in the same browser; they are not a claim that all
IDE operations or GPU rendering have the same speedup.

## Tests

`npm run test:classic-html` runs deterministic bevel pixel fixtures, authored
geometry comparisons, theme nesting, focus/disabled/pressed and forced-colors
checks, retained-list behavior and a same-browser comparison with the former
list paint implementation. Reports go to `reports/classic-html`.
The integer-DPI fixtures test exact staircase pixels. Fractional-DPI tests check
geometry and provide screenshots; browser font rasterization and native widget
popups are not claimed to be universal native Windows VB6 golden matches.

All output bundles are regenerated by `npm run build`. These CSS/JS changes
work in the original HTML renderer, without enabling the experimental GPU UI
renderer or changing backend preference on `main`.
